# تقرير جاهزية الإصدار النهائي 8.1.3

## نطاق الجولة

تم تنفيذ جولة تحسين مركزة على جودة المحتوى، اتساق الإصدار، قواعد Firestore، التوزيع، ولوحة التحكم. حافظت التغييرات على Kotlin وJetpack Compose وFirebase وRoom وMedia3 وHilt دون إنشاء مشروع بديل أو إدخال أسرار في المستودع.

## الإصلاحات المنفذة

| المجال | الإجراء | النتيجة |
|---|---|---|
| تنظيف المحتوى | إنشاء `ContentSanitizer` موحد لمنع السجلات الفارغة والقيم التجريبية المعروفة مثل `oussama` و`200`. | مزامنة Firestore والشاشة الرئيسية تستخدمان القاعدة نفسها. |
| الأخبار | منع عرض أخبار قابلة للتشغيل إذا كان العنوان أو الرابط قيمة تجريبية أو فارغة. | لا تصل السجلات التجريبية إلى بطاقة الأخبار الرئيسية. |
| الاختبارات | إضافة `ContentSanitizerTest` بثلاث حالات اختبارية. | يغطي الفراغات والقيم التجريبية والمحتوى العربي الحقيقي. |
| Firestore | إزالة الفهارس الأحادية غير الضرورية التي كان Firestore يرفضها، والإبقاء على الفهارس المركبة المطلوبة. | تم نشر القواعد والفهارس بنجاح إلى مشروع الإنتاج. |
| الإصدار | تحديث Android والتوثيق ولوحة الإدارة وصفحة التحميل إلى `8.1.3`, `versionCode 26`. | لا توجد مراجع تشغيلية متبقية للإصدار 8.1.2 في الملفات الأساسية. |
| التوقيع | إعادة توقيع APK باستخدام keystore الإصدار الرسمي والتحقق منه. | APK يتحقق عبر Signature Scheme v2 وv3 وبعدد موقّعين يساوي واحداً. |
| Hosting | تحديث صفحة التحميل والأصل Base64 وSHA-256 ولوحة الإدارة. | تم نشر Hosting بنجاح. |

## نتائج التحقق

- `testDebugUnitTest`: ناجح.
- `compileDebugKotlin`: ناجح.
- `lintDebug`: ناجح دون أخطاء قاتلة.
- اختبارات Functions: 10/10 ناجحة.
- اختبارات Firestore Rules المحلية: ناجحة وفق مجموعة الاختبارات الحالية.
- نشر Firestore Rules وIndexes: ناجح.
- بناء `assembleRelease` و`bundleRelease`: ناجح.
- APK: موقّع ومتحقق عبر v2 وv3.
- Firebase Hosting: منشور على `https://elwataniatvapp.web.app`.

## ملاحظة تشغيلية مهمة

Cloud Functions لم تُنشر لأن مشروع Firebase على خطة Spark يتطلب Blaze لتفعيل Cloud Build وArtifact Registry. هذا ليس فشل بناء في الكود؛ إنه قيد خطة Firebase. وظائف التعليقات والإشعارات موجودة ومختبرة محلياً، لكن تفعيلها الإنتاجي يتطلب ترقية المشروع ونشرها بشكل منفصل.

لم يتوفر محاكي Android قابل للتشغيل في بيئة التنفيذ بسبب غياب KVM، لذلك لا يتضمن هذا التقرير ادعاء اختبار بصري على جهاز حقيقي. يلزم اختبار قبول ميداني على هاتف أو محاكي يدعم KVM للبث الحقيقي، تبديل القنوات، App Check، الإشعارات، وRTL في أحجام متعددة.
