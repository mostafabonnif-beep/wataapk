# تقرير فحص روابط Firestore

تاريخ الفحص: 2026-09-22

تمت قراءة Firestore بحساب الخدمة دون تعديل أي بيانات، ثم فحص الروابط الموجودة في المجموعات المطلوبة: `streams` و`archive` و`social` و`websites`.

## النتيجة

- إجمالي المستندات: 13
- إجمالي الروابط المفحوصة: 13
- روابط استجابت بنجاح HTTP 200: 11
- أخطاء HTTP 404 مؤكدة: لا يوجد
- روابط تحتاج تحققاً من مصدر البث: 2

## الروابط التي لم يمكن تأكيدها

| المجموعة/المستند | الحقل | الرابط | النتيجة |
|---|---|---|---|
| `streams/live_main` | `url` | `https://itserverlab.2bd.net:5443/WebRTCApp/streams/stream.m3u8` | DNS يعمل، لكن الاتصال انتهى بمهلة 15 ثانية؛ ليس 404 مؤكداً |
| `streams/yt_watania` | `logoUrl` | `https://cdn.elwatniatv.dz/wp-content/uploads/2026/01/al-watania.png` | اسم المضيف لا يُحل عبر DNS؛ الرابط غير متاح حالياً من الخادم |

## الروابط السليمة

- قنوات YouTube الثلاث في `streams`: HTTP 200.
- رابط الأرشيف ورابط صورة الأرشيف: HTTP 200.
- روابط `social` الثلاث: HTTP 200.
- روابط `websites` الثلاث: HTTP 200.

## الإجراء المقترح

1. فحص مصدر `live_main` من خادم البث نفسه أو استبداله برابط HLS يعمل؛ مهلة الشبكة لا تكفي للحكم بأنه محذوف.
2. استبدال `logoUrl` الخاص بـ `yt_watania` برابط من Firebase Storage أو رابط CDN صحيح، لأن نطاق `cdn.elwatniatv.dz` لا يملك سجل DNS حالياً.
3. إعادة الفحص بعد تعديل الرابطين من لوحة التحكم.
