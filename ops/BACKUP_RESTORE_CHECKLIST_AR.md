# قائمة النسخ الاحتياطي والاستعادة — Elwatania TV

## المبدأ

بيانات Firestore وFirebase Storage بيانات تشغيلية للمؤسسة، ولا تكفي نسخة GitHub أو نسخة APK لحمايتها. يجب تنفيذ النسخ من مشروع Google Cloud أو Firebase رسمي، مع فصل حساب التشغيل عن حساب المطور.

## الجدول التشغيلي

| الأصل | التواتر | الاحتفاظ | اختبار الاستعادة |
|---|---|---|---|
| Firestore | يومي | 30 يوماً، مع نسخة أسبوعية وشهرية | مرة كل شهر في مشروع اختبار |
| Firebase Storage | يومي أو حسب حجم الوسائط | وفق سياسة المؤسسة | استعادة ملف عينة كل شهر |
| إعدادات Firebase العامة | عند كل تغيير | في مخزن أسرار المؤسسة | تحقق من عدم وجودها في Git |
| keystore وشهادة التوقيع | بعد كل تغيير مع نسخة ثابتة | نسختان مشفرتان منفصلتان | تحقق من إمكانية القراءة دون نشر السر |
| تقارير Crashlytics | أسبوعي في الشهر الأول | حسب سياسة المؤسسة | مراجعة يدوية |

## خطوات قبل التفعيل

يجب تفعيل Firestore وStorage من Firebase Console، اختيار الموقع المناسب، مراجعة قيود الخطة، وإنشاء حساب خدمة مخصص للنسخ الاحتياطي بصلاحيات أقل ما يمكن. لا تُحفظ ملفات حساب الخدمة أو كلمات المرور في المستودع أو داخل جهاز المشغل.

تفعيل Firebase Storage يتطلب فتح **Firebase Console → Storage → Get started**. قواعد المستودع موجودة في `storage.rules`، لكن نشرها لا يمكن أن ينجح قبل إنشاء Storage في المشروع. بعد الإنشاء يجب نشرها بالأمر التالي من بيئة موثوقة:

```bash
firebase deploy --only storage --project elwataniatvapp
```

## اختبار الاستعادة

تُستعاد نسخة Firestore إلى مشروع اختبار لا إلى المشروع الحي. تُقارن أعداد الوثائق في `streams` و`archive` و`epg` و`websites` و`social`، ثم تُفتح عينة من التطبيق أو لوحة الاختبار. بالنسبة إلى Storage، يُستعاد ملف صورة أو فيديو عينة ويُتحقق من نوعه وحجمه ورابطه، ثم يُحذف من مشروع الاختبار.

بعد كل اختبار يُسجل التاريخ، رقم النسخة، عدد الوثائق، حجم الوسائط، مدة الاستعادة، اسم المشغل، وأي اختلافات. لا يُعتبر الاختبار ناجحاً إذا تمت استعادة الملفات دون تطبيق القواعد الأمنية أو دون التحقق من القراءة والكتابة حسب الدور.

## مؤشرات فشل تستوجب التصعيد

يجب إيقاف أي نشر إذا كانت النسخة القديمة مفقودة، أو كانت الاستعادة تغير محتوى الوثائق، أو كانت قواعد Storage تسمح بالكتابة العامة، أو كانت ملفات الحساب أو المفاتيح ظاهرة في السجل. عند تجاوز حد الإنفاق، يُوقف رفع الوسائط وتُراجع السجلات قبل إعادة التشغيل.

## المسؤولية

تفعيل الخطة، إنشاء النسخ المجدولة، واختبار الاستعادة إجراءات تشغيلية لا يمكن تنفيذها بأمان من داخل المستودع وحده. يسجل المسؤول النتيجة في دليل التشغيل، ويحتفظ بنسخة خارج GitHub.
