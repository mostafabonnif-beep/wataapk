# قائمة القبول الميداني — Elwatania TV 8.1.9

## الهدف

تُستخدم هذه القائمة قبل اعتماد الإصدار **8.1.9 / build 32** كتطبيق المؤسسة. الاختبارات الآلية تثبت سلامة الكود والقواعد، لكنها لا تستبدل تجربة APK على أجهزة فعلية وشبكات مختلفة.

## اختبارات RTL والأحجام

يجب تجربة الاتجاه العربي على كل جهاز مع عناوين قصيرة وطويلة، وأسماء قنوات متعددة الكلمات، ورسائل خطأ طويلة. يجب أيضاً فحص البطل الرئيسي، بطاقة البرنامج التالي، رأس الأرشيف، بطاقات Social/Websites، شريط التنقل، سجل المشاهدة، Onboarding، GlobalErrorBoundary، وDialogs الإعدادات. عند غياب Firebase مؤقتاً يجب أن يظهر fallback مترجم بلا نص عربي صلب أو خبر عاجل تجريبي. يُقبل الاختبار عندما لا يحدث قص للنص، ولا يتداخل العنوان مع الأيقونات، وتبقى أزرار التنقل قابلة للضغط، ويظهر شريط التنقل السفلي بالترتيب العربي المتوقع.

يُعاد الاختبار بعد تدوير الجهاز من عمودي إلى أفقي وأثناء وجود المشغل مفتوحاً. كما تُفحص أحجام الخطوط الكبيرة وإعدادات الوصول في النظام، لأن نجاح العرض في الحجم الافتراضي لا يثبت نجاحه مع تكبير الخط.

## اختبارات لوحة التحكم والأدوار

| الدور | الإجراء | معيار القبول |
|---|---|---|
| Admin | تسجيل الدخول وفتح جميع التبويبات | كل التبويبات المسموحة تعمل، والإعدادات الحساسة متاحة فقط له |
| Editor | تسجيل الدخول بحساب يحمل `role: editor` | تظهر لوحات المحتوى التحريري فقط، وتُرفض كتابة `config` |
| Moderator | تسجيل الدخول بحساب يحمل `role: moderator` | لا تظهر لوحات المحتوى، ويمكن تنفيذ مسار الإشراف المعتمد فقط |
| حساب عادي | تسجيل الدخول دون claim | يُرفض الدخول ولا تظهر لوحة البيانات |
| انتهاء الجلسة | تسجيل الخروج ثم العودة للرابط | تعود صفحة الدخول ولا تبقى بيانات اللوحة معروضة |

## Crashlytics وAnalytics

بعد تثبيت Release، يُفتح التطبيق مرة واحدة مع اتصال بالإنترنت، ثم تُراجع Firebase Console بعد فترة المزامنة. يجب ظهور إصدار التطبيق **8.1.9 (32)** ضمن Crashlytics أو Analytics دون تسجيل بريد أو كلمة مرور أو بيانات شخصية حساسة. إذا لم تظهر البيانات، تُسجل لقطة شاشة ورسالة Console ولا تُعاد محاولة النشر عشوائياً.

## ملاحظة عن المحاكي غير المتسارع

إذا استُخدم AVD على خادم بلا KVM وظهرت رسائل `System UI isn't responding` أو `Permission controller isn't responding` أو فشل `StorageManagerService.allocateBytes` أثناء تثبيت الحزمة، تُسجل كمشكلة بيئة ولا تُقبل كدليل على crash داخل التطبيق. في الجولة الحالية جرت محاولة `-no-accel` و`-wipe-data`، لكن المحاكي وصل إلى خدمات جزئية وفشل تثبيت APK بسبب عدم اكتمال system providers وظهور NPE/IllegalStateException في PackageManager؛ لذلك يجب إعادة الاختبار على جهاز فعلي أو AVD مدعوم بتسريع عتادي قبل إصدار حكم نهائي.
