# دليل تشغيل وتسليم الوطنية TV

## الهدف

هذا الدليل يحدد الطريقة الآمنة لتشغيل التطبيق ولوحة التحكم في الإنتاج، والتحقق من الإصدار، وحماية بيانات المؤسسة، والتعامل مع الأعطال. لا يحتوي الدليل على مفاتيح أو كلمات مرور أو ملفات توقيع.

## قبل اعتماد أي إصدار

يجب تشغيل اختبارات الوحدة وLint وبناء Release، ثم تشغيل `scripts/verify-release.sh` على APK الناتج. يجب حفظ SHA-256 في سجل الإصدار ومقارنته بالملف المنشور في صفحة التحميل. لا يُسلَّم أي APK إذا لم يكن الإصدار موقّعاً عبر شهادة المؤسسة نفسها.

## حسابات لوحة التحكم

يُنشأ حساب مستقل لكل مشغّل في Firebase Authentication، ولا تستخدم المؤسسة حساباً مشتركاً. تُمنح الصلاحية عبر `scripts/set-admin-claim.js <email-or-uid> [admin|editor|moderator]`. المسؤول `admin` يملك الصلاحيات الكاملة، والمحرر `editor` يدير المحتوى التحريري، والمشرف `moderator` يملك صلاحية حذف التعليقات المبلغ عنها فقط. يستمر دعم `admin: true` القديم. بعد تغيير الصلاحية يجب تسجيل الخروج وإعادة تسجيل الدخول لتجديد ID token، وتُحفظ قائمة الحسابات خارج المستودع.

## النسخ الاحتياطي

تحتاج النسخ الاحتياطية المجدولة لـFirestore وStorage إلى تفعيل خطة Firebase المناسبة أو تشغيلها من مشروع Google Cloud مخصص. يجب تنفيذ نسخة يومية، والاحتفاظ بنسخ أسبوعية وشهرية، واختبار الاستعادة مرة كل شهر. لا تعتبر نسخة GitHub بديلاً عن نسخة بيانات Firestore. قبل استخدام Storage يجب فتح Firebase Console → Storage → Get started، اختيار الموقع، ومراجعة سياسة الفوترة؛ لا ينفذ المستودع هذا الإجراء تلقائياً.

## Cloud Functions

وظائف الإشعارات وسجل التدقيق تختبر محلياً، لكن نشرها يتطلب أن تسمح خطة Firebase بخدمات Cloud Build وArtifact Registry. قبل التفعيل، راجع التكلفة، ضع حدود إنفاق وتنبيهات، ثم نفذ النشر من بيئة موثوقة. بعد النشر، اختبر الإشعار وسجل التدقيق من حساب محرر وحساب مدير.

## مراقبة الإنتاج

أصبح التطبيق يهيئ Crashlytics وAnalytics في Release فقط عند وجود Firebase، مع تسجيل نسخة التطبيق ورقم البناء. يجب تفعيل Crashlytics وAnalytics وPerformance Monitoring من Firebase Console وفق سياسة الخصوصية المعتمدة، ثم تثبيت APK Release على جهاز اختبار وفتح التطبيق وإرسال حدث تجريبي غير حساس. راقب تعطل المشغل، زمن بدء البث، فشل المصادقة، وفشل مزامنة Firestore. تُراجع التقارير أسبوعياً في الشهر الأول من الإطلاق.

## قبول الهاتف

يجب اختبار APK على هاتف صغير، هاتف متوسط، جهاز لوحي، وجهاز Android TV إن كان مدعوماً. تشمل قائمة القبول: اتجاه RTL، النصوص الطويلة، تشغيل البث، تبديل القنوات، إيقاف واستئناف التطبيق، انقطاع الشبكة، تسجيل الدخول، الإشعارات، الأرشيف، EPG، وتثبيت التحديث فوق الإصدار السابق.

## سياسة الحوادث

عند توقف البث، يراجع المسؤول رابط المصدر في Firestore ثم يختبره خارج التطبيق. عند فشل اللوحة، لا تُحذف البيانات لإعادة التجربة؛ تحفظ لقطة من رسالة الخطأ وسجل المتصفح ويُراجع آخر تغيير. عند اكتشاف حساب غير مصرح به، يُلغى المستخدم فوراً وتراجع قواعد Firestore وسجل التدقيق.

## بيانات التسليم

تتضمن حزمة التسليم APK وAAB، SHA-256، سجل التوقيع، رابط صفحة التحميل، رابط لوحة التحكم، هذا الدليل، سياسة الخصوصية، وتعليمات إعداد الأدوار وcustom claims. يجب أيضاً تسليم نتيجة اختبار Emulator وقواعد Storage وسجل نشر Hosting. يبقى keystore وكلمات مروره في مخزنين آمنين منفصلين ولا تُرفع إلى GitHub.

## متغيرات بناء لوحة الإدارة

يُبنى Firebase Hosting الآن من دون تخزين تهيئة Web داخل المصدر. قبل تنفيذ `firebase deploy --only hosting` يجب توفير المتغيرات التالية في بيئة البناء المحلية أو CI، ثم تشغيل النشر من جذر المشروع:

```text
FIREBASE_WEB_API_KEY
FIREBASE_WEB_PROJECT_ID
FIREBASE_WEB_AUTH_DOMAIN
FIREBASE_WEB_STORAGE_BUCKET
FIREBASE_WEB_MESSAGING_SENDER_ID
FIREBASE_WEB_APP_ID
FIREBASE_WEB_MEASUREMENT_ID   # اختياري
```

يكتب `scripts/build-hosting.js` ملف `admin/firebase-config.js` داخل شجرة النشر المؤقتة فقط، وهو ملف تهيئة Web عامة وليس service-account أو كلمة مرور. لا تُحفظ قيم البيئة في GitHub، ولا ينبغي استخدام هذا المسار لتخزين أي مفتاح خاص أو بيانات اعتماد إدارية.
